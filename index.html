Red Hat OpenShift Data Foundation · ODF 4.18

One storage layer for block, file and object, running inside OpenShift.

ODF packages Ceph, Rook and the Multicloud Object Gateway as operators. Your apps ask for storage with an ordinary PVC or bucket claim. Ceph stores three copies of every write, each in a different failure domain.

    What gets installed

    The stack, from the bottom up

    You install one operator from OperatorHub, the ODF operator. It installs and manages everything else in the openshift-storage namespace.

    Ceph (RADOS)the storage engine

    Pools data across many disks and keeps it replicated and self-healing. Clients compute where data lives with the CRUSH algorithm, so no central lookup sits on the data path.

    MON × 3 · cluster mapMGR · metricsOSD · one per diskMDS · CephFS metadataRGW · S3 (on-prem)
    RookCeph operator

    Deploys Ceph daemons as pods, replaces failed OSDs, and handles upgrades. It turns a StorageCluster custom resource into a running Ceph cluster.

    Ceph-CSIKubernetes drivers

    Provisions, attaches, resizes, snapshots and clones volumes when a PVC asks for one of the ODF storage classes. CSI-Addons adds reclaim-space, key rotation and volume replication for DR.

    ocs-storagecluster-ceph-rbdocs-storagecluster-cephfs…-ceph-rbd-virtualization
    Multicloud Object GatewayNooBaa

    An S3 endpoint that can store buckets on Ceph, AWS S3, Azure Blob, GCS or other S3-compatible stores. It adds mirroring, namespace buckets and caching across them. Apps request buckets with an ObjectBucketClaim.

    ODF operator + consolethe front door

    Ties it all together with the Data Foundation pages in the OpenShift console: capacity, health, alerts and the create-StorageSystem wizard.
